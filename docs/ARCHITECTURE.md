# 架构与安全边界

## 数据流

```text
官方桌面微信本地数据（微信完全退出时）
        |
        v
带完成标记的离线数据库副本
        |
        v
wechat-cli
  - 账号目录定位
  - 数据库密钥映射
  - WCDB 只读查询
  - 消息标准化
        |
        | call-json
        v
Wetrace Python 分析器
  - 分页与范围控制
  - 统计与聚合
  - JSON/CSV/TXT/HTML
        |
        v
Codex / 其他 Agent
  - 摘要
  - 待办判断
  - 简报和报告
```

## 组件职责

### wechat-cli

负责与微信本地数据格式打交道。它返回稳定 JSON，不负责生成主观关系结论。

数据库通过 WCDB/SQLite 只读标志打开。正常读取可能为名称索引、图片解码和语音转写写入辅助缓存；`--strict-read-only` 会禁用这些辅助写入。

### Wetrace

负责将 `wechat-cli` 的消息结果转成统一统计：

- 只接受 `WETRACE_OFFLINE_DB_ROOT` 指定且带完成标记的离线副本
- 强制覆盖 `WECHAT_CLI_DB_ROOT`，避免误读微信正在使用的在线目录
- 单会话完整分页
- 跨会话限制与失败隔离
- 时间、成员、类型和词频聚合
- 截断披露
- 本地报告生成

Wetrace 不连接旧版 `127.0.0.1:5200` 服务，也不运行独立数据库解密逻辑。

### Agent

Agent 负责需要自然语言理解的工作，例如摘要、待办、主题归纳和报告撰写。

这些结论必须引用明确的数据范围，不能把沟通频率直接解释为真实感情或关系质量。
Wetrace 适配器本身不把聊天数据发送到网络，但 Agent 的数据处理位置与保留策略由所使用的平台和配置决定。

## 写入边界

### 微信数据库

只读。Wetrace 不提供发送、删除、修改、标记已读或标记未读的代码路径。

### 本地支持文件

普通 `wechat-cli` 模式可能写入：

- 数据库密钥配置
- 名称和会话元数据索引
- 图片解码缓存
- 语音转写缓存

严格只读模式禁用这些写入。

### Wetrace 输出

用户要求导出或仪表板时，Wetrace 会写入：

```text
~/wetrace-exports/
```

或用户指定路径。该写入不接触微信数据库。

## 官方客户端副作用

只读 CLI 无法约束官方桌面微信。以下行为可能由官方客户端同步到手机：

- 登录桌面微信
- 打开聊天
- 播放语音
- 查看媒体

因此“CLI 只读”不等于“整个操作流程不会改变未读状态”。Wetrace 现在强制使用离线副本；创建副本时要求微信进程已经完全退出，分析时不需要启动微信。

## Windows 密钥扫描

Windows 扫描只接受通过真实数据库验证的候选。扫描统计不输出进程 ID 到最终失败诊断，避免不必要的信息暴露。

当前扫描路径：

1. 收集目标数据库 salt。
2. 枚举官方微信进程的可读内存区域。
3. 搜索 ASCII、UTF-16 和二进制候选。
4. 对候选去重并限制每个 salt 的数量。
5. 逐个尝试真实数据库验证。
6. 仅保存验证成功的密钥。

兼容性会随微信版本变化，必须用真实消息正文作为最终验收。
